# 验收记录与实际接入清单

## 自动化验证

`uv run pytest -q` 覆盖：

| 场景 | 验证内容 |
| --- | --- |
| 单聊、群聊文本 | 统一事件、过滤非目标消息、@ 本机器人而非普通用户 |
| 白名单 | 用户/会话分别过滤、同时匹配、App ID 隔离 |
| 重复消息 | 相同消息重复 envelope 仅创建一条记录 |
| 官方 SDK 接收确认 | 使用真实 dispatcher 和 WS ACK 编码，提交后返回 200；模拟存储失败返回 500 |
| 发送与回复 | 官方 request builder、稳定 uuid、出站共同顺序 |
| HTTP 鉴权/幂等 | 401、202、重复键复用、内容冲突 409、校验错误 422、统一错误 |
| 下游故障 | 5xx/429/网络超时重试，4xx/重定向死信，退避、其他会话不阻塞 |
| 顺序与重放 | 死信阻塞本会话，重放后按原位置继续 |
| 重启恢复 | processing 任务恢复并使用原 delivery ID 发送 |
| 安全性 | 签名校验、篡改/过期拒绝、日志密钥脱敏 |
| 生命周期 | 就绪状态、优雅退出、同数据目录排他锁 |
| 发布脚本 | 官方 GraphQL 请求格式、GraphQL 错误、完整 SHA 校验、健康与版本等待 |

PR 和主分支还执行 lint、类型检查、OpenAPI 同步、容器构建与 smoke test。容器测试使用假飞书配置，只验证进程/端口/非 root/数据库及重启，**不能替代真实飞书和 Zeabur 联调**。

## 需要真实环境执行

配置见 [deployment.md](deployment.md)。每项应记录时间、SHA、事件/投递 ID 和结果，避免保存密钥或敏感消息正文。

- [ ] 飞书单聊发文本，Webhook 收到统一事件，签名通过。
- [ ] 群内 @ 机器人收到事件；不 @ 或 @ 普通用户不转发。
- [ ] 白名单内允许，白名单外忽略。
- [ ] API 发消息和回复在真实飞书会话可见，状态查询 succeeded。
- [ ] 下游临时返回 503，恢复后按同会话原顺序投递；重复 delivery ID 不重复执行业务。
- [ ] 下游持续故障产生死信，修复并调用重放后恢复。
- [ ] 队列中存在未完成任务时重启 Zeabur 容器，确认记录保留并恢复。
- [ ] 合并一条测试提交到 main，Actions 检查成功、GHCR 新 SHA 可见、Zeabur 自动更新。
- [ ] `/healthz`、`/readyz`、`/v1/status` 显示目标 SHA，长连接恢复。
- [ ] 手动指定历史 SHA 回滚，版本校验通过，持久卷记录保留。

未完成以上真实环境项目时，不应把“本地测试通过/流水线已提供”标记为“生产验收完成”。
