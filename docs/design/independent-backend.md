# 独立飞书实时转发服务：已采纳设计

状态：已按此设计实施源码；离线测试与真实环境验收分别记录在 [验收清单](../acceptance.md)。服务尚未部署，不提供旧接口兼容或迁移方案。当前 HTTP/WS 协议以 [api.md](../api.md) 为准。

## 边界

飞书接入适配器 → 有界内存事件分发 → 获授权的在线 WebSocket 连接。发送/回复由 HTTP 和 WS 共用命令服务，直接等待飞书响应。

网关只负责平台连接、技术授权、协议转换、在线过滤、实时转发和运行保护。客户端负责业务身份、工作流、上下文、消息历史、持久去重、待发送任务和订阅配置保存。第一版单实例、单飞书应用；不假设使用方是 AI、工作流或某种账户。

不保存消息历史和持久投递队列，允许丢失和重复，不保证离线重放。内存缓存和 socket 缓冲仍是临时状态，均有明确边界。SDK 确认不等于客户端确认。准确的运行保证见 [operations.md](../operations.md)。

## 权限与订阅分离

鉴权解决持有什么凭证，授权解决能执行什么操作、访问哪些资源，订阅只描述在已授权范围内想接收什么事件。

权限采用操作与资源的组合：`events.receive`、`messages.send`、`messages.reply`、`status.read`，资源为 `app_id` 和 `chat_ids`。多个 grant 取并集，不隐含业务角色；订阅在 grant 内继续按会话、发送者过滤。显式订阅越权范围整体拒绝；省略过滤条件不会越权。

授权配置由受信管理端通过签发 API 写进短期 HS256 JWT。网关只持有启动管理令牌和独立签名密钥，不建立账户注册表或权限数据库。这个简化选择的代价是：逐个令牌不能立即撤销，权限变更不会追溯撤销旧令牌，长期运行的客户端需要受信签发者续签。到期会关闭 WS；紧急撤销全部凭证可轮换签名密钥并重启。若未来明确要求逐个即时撤销，应另行增加凭证注册/撤销存储，而不是声称 JWT 本身具有这项能力。

## ID 与路由

| ID | 归属与用途 |
| --- | --- |
| `principal_id` | 管理端分配的稳定技术身份，来自已验签凭证 |
| `connection_id` | 一次 WS 连接，服务器生成，重连改变 |
| `subscription_id` | 连接内的临时过滤规则标识，客户端指定 |
| `session_id` | 客户端命令关联标签，原样回传，不建会话表，不参与授权 |
| `conversation_id` | 按真实飞书 App ID + chat ID 生成的来源标识 |
| 请求 `id` | WS 请求/响应关联，不等于幂等键 |
| `idempotency_key` | 客户端保存的一次发送意图，跨连接和重启复用 |

一个连接承载多段对话。订阅不需要 callback 地址；HTTP API 仍可独立调用。每个客户端保存自己的来源元数据，以真实 `message_id` 提交回复。回复前网关向飞书查询实际会话再授权；不使用客户端声称的 chat ID 或可变 `last_route`。

## 分发规则

同一连接相互重叠的订阅合并为一份事件，附匹配订阅 ID 列表。不同授权连接各自收到一份，即广播。网关不选择谁应处理、谁应回复，不实现竞争消费或会话独占。多个客户端是否重复执行业务，由调用方安排。

订阅绑定连接，断线即删除。重连重新认证并重新提交订阅，仅接收建立订阅后的实时事件；没有 ACK/NACK、消费游标、租约、死信或恢复 API。每连接已排队事件串行写出，超限关闭慢连接，释放临时内存。

## 出站与幂等

发送/回复同步返回明确成功、明确拒绝或结果不确定，不返回暗示持久受理的 202。HTTP 与 WS 共享权限、并发额度、内容指纹及短期结果缓存；连接取消不会撤回已经开始的发送。

按应用、principal、操作和客户端幂等键生成稳定 UUID。飞书一小时窗口内的 UUID 去重能力作为上游有限保证，客户端仍需保存原请求；网关不承诺跨重启结果查询、永久幂等或自动重试。失去响应后必须按结果不确定处理。

## 首版范围

已实现 WS 双向协议、HTTP 发送/回复、管理签发、限时权限、临时订阅、广播、入站白名单、官方 SDK 监督重启、内存上限、统一错误、运行状态、Docker 与 SHA 发布流水线。

Webhook 可作为后续独立传输适配器，通过 API 管理其配置；首版不实现 Webhook 注册或投递，不把地址设成必填环境变量。RPC 当前承载于 WebSocket JSON 帧，不实现 gRPC。多应用同实例、跨实例路由、凭证逐个撤销、竞争消费和持久重放也不在首版。

容器无消息持久卷，使用非 root 用户，保留 PORT、健康检查、单环境串行部署、版本验证及手动指定 SHA 回滚。重启和部署存在接收空窗，客户端需重连；无数据库不等于高可用。
