# 运行语义与边界

## 数据与顺序

网关提供 best effort 实时转发。无在线订阅时释放消息，断线和重启后不重放。官方 SDK 可能重复送达事件；客户端落盘前的消息丢失不能通过其本地数据库恢复。不要宣称 exactly-once 或严格 at-most-once。

SDK 子进程将规范化事件写入有界、非阻塞的 socket pair。回调返回允许官方 SDK 确认接收，此时主进程甚至可能还没读到事件；确认不代表下游接收或业务完成。IPC 超限/写入不完整会结束接收进程并丢弃残帧，监控随后重启；上游是否重发不作为服务保证。

应用只在内存中保留连接、订阅、待写帧、在途命令及最多一小时的幂等元数据。完成的命令缓存保存指纹、结果 ID/错误类别，不保存异常 traceback 和正文；每五秒清理过期已完成条目。进行中的命令保留至完成。没有数据库、消费游标、死信或归档。

每连接串行写出已经接收且成功排队的事件。此顺序不覆盖断线缺口、平台生成顺序或客户端并行处理完成顺序。发送请求可跨连接/HTTP 并发，不保证会话内出站排序；有此要求的客户端须自行串行发送。通过 `message_id` 回复，避免用可变的 session 最后来源推断目的地。

## 内存、压力和隔离

默认每连接 100 条/1 MiB，所有连接待写帧总预算 32 MiB；计数包含已出队但尚未完成写出的帧。任一单连接预算超限或写超时则关闭该连接、清理剩余帧。总预算不足时拒绝当前帧并关闭其接收连接，释放它的待写队列；不新增无限等待队列。

连接数包含尚未鉴权连接，鉴权限时 10 秒。Uvicorn 固定使用 `websockets` 后端，限制 WS 输入帧大小和最多四条输入队列，禁用压缩；HTTP 请求体默认最多 64 KiB。出站 SDK 调用默认最多 16 个，回复归属查询共享额度。取消/超时的调用仍占用额度，直到实际 SDK 调用结束，防止利用反复断开创建无界后台调用。实例级限额不提供客户端之间的公平调度保证。

`TOTAL_BUFFER_BYTES` 只统计应用待写帧，不是总进程内存。HTTP 并发、协议库、SDK 分片缓存、内核 socket 缓冲和 Python 对象仍有开销。容器应设置内存上限，并依据真实并发和消息大小进行负载验证。单实例/单 worker 是部署约束，多个 worker 会各自建立上游连接，无法保证正确广播。

## SDK 生命周期与退出

官方 SDK 自带重连。固定 `lark-oapi==1.7.3` 在独立进程中运行，避免其同步连接发现阻塞 HTTP 服务。适配器目前使用 SDK 的 `_conn`、`_disconnect`、`_auto_reconnect` 和模块事件循环；升级必须复核这些私有接口和契约测试。Uvicorn 的 `websockets` 后端已有弃用提示，当前固定版本仍支持；将来更换后端时必须重新验证输入背压、队列限制和日志脱敏，不能直接沿用不生效的配置。

父进程每五秒检查 SDK 子进程。其事件循环超过 90 秒没有活动时先终止，下次检查仍未退出则 kill，然后重建 IPC 并重启。监控不会在 API 事件循环中等待进程 join。心跳超过十秒不更新则 readiness 失败。获取机器人身份失败时每五秒重试，应用错误详情不会写入日志。

SIGTERM 时 Uvicorn 停止接入并关闭连接；应用取消入站循环、关闭子进程、等待在途 SDK 请求。排队事件直接释放，不等待客户端落盘。SDK HTTP 超时限制单次网络等待，并不等于严格端到端总期限；客户端等待、Uvicorn 宽限及平台终止宽限共同限制退出，建议平台至少给 60 秒，最终 kill 仍可能留下结果不确定的发送。

## 观测和日志

`/healthz` 只表示进程存活，不能据此判断飞书已连接。`/readyz` 还检查 SDK 心跳及接收循环。`/v1/status` 需要 `status.read`，没有活跃订阅也可以就绪。

- `received`：主进程读取的规范化事件数；重复事件也计数。
- `unrouted`：没有匹配在线订阅的事件数。
- `dropped`：应用缓冲拒绝/清理的帧数，包含事件及 RPC 响应；不代表唯一飞书消息数。
- `slow_consumers`：单连接缓冲超限或写超时次数。
- `buffered_bytes`：全部应用连接缓冲字节数，包括在途写出。
- `receiver_restarts`：当前主进程观察到的 SDK 重启次数。
- `outbound_completed` / `outbound_failed`：实际完成的 SDK 发送调用次数 / 其中错误次数，包含显式重试，不包含缓存命中及归属查询。
- `last_outbound_result`：最近完成发送的 status、错误 code 和秒级 Unix completed_at；不保存正文、来源或消息 ID。启动后尚无结果时为 null。

所有计数仅覆盖当前 `boot_id`，重启归零。SDK 接入前或停机期间的消息丢失无法准确计数。应对长连接失联、子进程反复重启、缓冲占用和慢消费者告警。

日志只输出状态和安全的异常类型，对启动密钥脱敏，关闭 SDK/HTTP/WebSocket 依赖原始日志及 HTTP access log。错误响应不返回请求正文、鉴权帧或 SDK 响应正文。不要在平台代理、采集器中另行记录 Authorization 或 WS 原始帧。

## 客户端持久化

示例客户端用 `(app_id, message_id)` 唯一键，在本地事务提交后才进入业务处理。客户端也需要为自己的待发送消息保存目标、原文和稳定幂等键，并按业务规定清理自身数据库。网关不读取、备份或清理客户端数据库；没有网关数据库备份任务。
